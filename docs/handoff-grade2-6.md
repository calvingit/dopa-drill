# Handoff：二年级～六年级对齐北师大版数学教材

本文档交给接手对齐工作的 agent，自包含，冷启动可直接干活。

## 任务与硬规则

dopa-drill（本仓库）是纯前端计算练习应用。一年级计算内容已对齐北师大版《义务教育教科书·数学》一年级上、下册——提交 `2f0fb63 feat: align grade-1 skills with the BNU edition textbooks`，它的 diff 就是本任务的范例。你的任务：用同样的方法对齐 2～6 年级，一次一个年级，从二年级开始。

硬规则：每个年级的 app 内容 ⊆ 该年级北师大版课纲（修剪超纲），并补齐该年级教材有而 app 缺的计算内容（新增技能）。app 中出现在更晚年级的内容**不前移**（保留原技能作为后置年级的复习/格式练习），除非超纲。结构性取舍超出此政策时（如技能需跨年级大挪移），先问用户再动手。

## 单一事实来源与数据流（先读这些，不必重新探索仓库）

- `app/js/skills.js`：SKILLS 数组是唯一课程来源，每行 `{id, name, grade, lane, req, gen:[生成器名, 参数]}`。改课程 = 改这里。
- `app/js/problems.js`：`GEN` 25 个生成器（compose/hadd/hsub/add3/kuku/vadd/vsub/vmul/vdiv/vdec/frac/gcdlcm/order/round/percent/ratio/letter…）。**优先复用现有生成器加参数**，确实没有形状才加新生成器。
- `app/js/session.js`：出题计划（年级模式按 DEPTH 排 easy→hard、加时赛取最难 45%、placement 沿全序跳检）。MASTERY 规则与跳跃大小不许改。
- quests/unlocks/收藏按 grade/lane 字段自动适应；唯 `app/js/trophies.js` 四个阶梯顶格值 = 技能总数（unlocked/mastered/star5 = 总数，starsTotal = 总数×5），技能总数变化时同步。
- 文档链必须同步：`docs/curriculum.md`（§1 计数表、§2 年级表、§3 生成条件）→ `docs/SPEC.md` §6.1 计数 → `README.md` 出处行；curriculum.md 开头「一年级已对齐、其余暂沿用」的声明随年级推进逐步改写。

## 教材 PDF 与阅读方法（省上下文的关键）

- 教材在 `北师大版/` 目录（12 个 PDF，一册一文件，未入库）。扫描版无文本层，用 Read 工具 `pages` 参数看图（每次 ≤20 页）。一年级两册的偏移是 **PDF 页码 = 书页码 + 4**，其他册先自行校验；目录在 PDF 第 4–5 页。
- 先读目录锁定计算单元，再只精读计算单元（每单元 15–30 页）。分类、比较、位置、认识图形、观察物体、钟表、测量（长度/质量/时间/年月日）、统计全部超出本应用范围（SPEC §6.1 排除），只在分析表标「不在范围」，不读细节。
- **把「按页码区间读 PDF、汇报每节课的课题/算式类型/精确数值范围/教材方法名」整包委托给 Explore 子代理**，只让它返回结构化文字结论，一次一个年级。

## 每个年级的固定流程

1. 读上、下册目录（PDF 页 4–5）。
2. 委托 Explore 精读计算单元，拿到逐课的范围与例题。
3. 对照现有技能出三类分析表：**对齐（不动）/ 超纲（收参数或依政策处理）/ 缺失（新增）**。
4. 定改动：复用生成器加参数（一年级轮新增过 `maxSum`/`allowEqual`/`max` 三个先例）；新技能命名沿用现有风格，id 用 gN- 前缀；**已有技能 id 一律不改**（localStorage 存档兼容，id 前缀与实际 grade 不一致可接受，在 curriculum.md 备注即可）。
5. 实现 skills.js + problems.js 小改。
6. 同步 curriculum.md（含给已对齐年级表加「北师大版单元」列）、SPEC §6.1、README、trophies 阶梯。
7. 跑验证（下节），单独提交，信息仿仓库风格如 `feat: align grade 2 to 北师大版`。

## 已知疑点（必须逐条对 PDF 求证，禁止凭记忆断言）

- **g2**：kuku 口诀顺序（dans [5,2]→[3,4]→[6,7]→[8,9,1]）是否与教材口诀单元一致；`g2-frac-of`（1/2、1/4）可能超纲（教材分数初步认识或在三年级）；教材二上的 100 以内连加连减混合（两位数三数链）app 没有，是否新增（顺带裁决一年级遗留缺口「整十数连加 10+30+50」）；表内除法、有余数除法在教材的年级位置。
- **g3**：三位数/四位数加减、两位数乘两位数、除法竖式的年级位置；「认识小数（元角分）」与 app 小数技能的口径衔接。
- **g4**：`g4-frac-mixed` 带分数加减是日式遗留，核实教材位置（可能五年级或弱化）；`order` 运算顺序 vs 教材「运算律」；`round` 对应大数单元的四舍五入口径。
- **g5**：`g5-percent` 百分数在教材可能属六年级；分数乘除法（教材五下）与 app g5/g6 的错位；gcd/lcm 对应「倍数与因数」单元。
- **g6**：比与比例、正比例反比例的位置；`g6-frac-dec` 小数分数混合的口径。
- 横向：教材「认识…」单元与「计算」单元要区分，app 只做计算。

## 生成器的坑（一年级轮踩过的）

- `hsub` 退位提示「破十法」文案只对一位数减数成立（已修为 y≤9 才用）；扩范围时检查 help 文案假设。
- `hadd` 有 50% 交换（会出现 5+74 这类）和 `tensToo` 30% 整十变体；写范围断言必须覆盖这两种形态。
- `carry:'yes'` 对一位数意味着和≥10（3+7=10 会出现，与 compose10 的凑十有意重叠，接受）。
- 签名空间太小的技能会在 `tests/app_generators.test.mjs` 防重复断言失败，照 compose10 先例（9 题、阈值 8）加例外。
- `buildH` 横式对多位数 token 通用（100−48 已验证）；竖式参数约束见 curriculum.md §3.2。
- 扩参数后写抽样脚本：每技能 120 题、正则解析 `p.text`、重算 carries/borrows、断言范围（`makeProblem` 的 recent 参数要传 `new Set()`）。

## 验证清单（每轮必做）

1. `node --test tests/*.test.mjs`（当前 58 项全过；TREE_LAYOUT、placement、防重复最可能受影响，最小化调整；SPEC §11.2 的测试件数若变也同步）。
2. 抽样脚本范围断言全过。
3. 字体：新技能名用字比对 `git show HEAD:app/js/skills.js` 字符集，缺字才跑 `tools/build_fonts.sh`（需 curl+uv）。
4. 文档三处 + trophies 阶梯同步。
5. 真机手感不在自动验证内：两位数内容落在低年级会继承更紧的连击窗口，报告里声明此局限，不要自行改 scoring。

## 边界

不改 MASTERY/placement/comboWindowMs/quests/unlocks/现有技能 id/二年级竖式起点；非计算单元不做；`北师大版/` PDF 不入库；全部文案简体中文、术语沿仓库现有用法；不 push、不 rebase，每年级独立提交、diff 只含该年级改动。

## 交付物

每年级一轮：对照分析表 → 代码+文档 diff → 测试与抽样证据 → 简短报告（改了什么、决策、遗留）。完成并验证二年级后再进下一个年级。
